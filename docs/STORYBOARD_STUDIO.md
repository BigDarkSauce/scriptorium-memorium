# Storyboard Studio

Storyboard Studio is a visual, source-grounded companion to the Scriptorium library. Open it from the title screen or visit storyboard.html when the project is served locally.

## Workflow

1. Choose a PDF or PPTX presentation. PDF imports use the existing Scriptorium chapter and subsection detection; PPTX imports preserve slide order, extract slide text, and expose embedded pictures as source figures.
2. Select the chapters or slides to analyse. For PDFs, the page range can further restrict the selection.
3. Choose complete, essential, or exact-card depth, then generate. Each selected part is analysed separately so source boundaries and citations remain visible.
4. Read the cards in sequence or use Present for a one-click, keyboard-driven presentation. The board remains horizontally scrollable; depth rows, side-topic placement and card width can be changed without moving or rebuilding individual cards.

## Images and source material

Each explanatory beat contains a pair of sentences and one image query. The image resolver searches Wikimedia Commons, admits only public-domain, CC0, CC BY or CC BY-SA material, and shows the file page, author when available, and licence. Requests and image downloads time out quickly; unavailable images become a search link rather than a spinning placeholder. Images are never generated by this feature.

PDF figure crops come from the existing js/ai/ingest.js extractor and retain their page/caption labels. When the director marks a page as especially useful, the original PDF page is rendered and attached as a source-page image. PowerPoint pictures are extracted directly from the PPTX package and shown as source figures. The PPTX reader extracts picture assets and text; it does not attempt to reproduce every slide theme, animation or layout as a full-slide screenshot.

## Diagrams and animation

Custom diagrams and charts are rendered locally as SVG from the storyboard's structured nodes, edges or data points. GeoGebra uses the official deployggb.js applet embedding interface; generated construction commands are sent through the GeoGebra applet API, not evaluated as JavaScript. Applet creation is deferred until the relevant card is rendered.

Manim Community runs as a Python renderer, not as browser JavaScript. When a card needs a Manim animation, the director returns a complete .py scene. Download that file and render it locally with the command shown on the card, for example:

    manim -pql scene.py ExplainConcept

The app does not execute generated Python code in the browser. Inspect a downloaded script before running it. Manim's official CLI and output options are documented at https://docs.manim.community/en/stable/guides/configuration.html.

## AI provider

Storyboard generation reuses the AI engine already configured in Scriptorium (js/ai/free.js and js/ai/claude.js). This includes the existing provider/key settings, and the same manual copy-prompt/paste-JSON fallback when no connected engine is available. The feature does not require a separate key when a Scriptorium provider is already configured.

## Current boundaries

- PDF chapter extraction and PDF figure extraction reuse existing Scriptorium code.
- PowerPoint extraction currently supports PPTX, not legacy PPT.
- The GeoGebra applet is live and interactive when GeoGebra's service is reachable.
- Manim code is generated and exportable; actual rendering needs a local Manim Community installation or a separately configured rendering service.
- Internet images depend on Wikimedia Commons availability and source licences. A timeout produces a fast fallback.
